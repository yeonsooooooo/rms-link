# 0.4.3 판독 복구

현장 보고: 오류 안내는 보이지 않았고 RMS 일부 정보만 수집됐습니다. 이벤트 내역 창에서도 텍스트는 늘었지만 연동되지 않았습니다. 해당 PC의 원문·화면·제조사 정보가 제공되지 않아 특정 현장 원인이나 호환성은 확정하지 않았습니다.

## 수정한 경로

- 접근성 탐색이 행의 직계 자식, 깊이 8, 형제 100개에서 중단되던 구조를 변경했습니다. 선택한 창의 Raw UIA 트리에서 중첩된 셀을 탐색하고, 셀 제목 대신 ValuePattern 값을 우선합니다. 보이는 셀의 좌표와 컨테이너를 기준으로 행을 구성합니다. 비밀번호와 화면·선택 영역 밖 텍스트는 제외합니다.
- 요소 하나의 조회 실패가 이미 확보한 모든 행을 버리던 문제를 수정했습니다. 탐색은 4,000개 요소·깊이 24·1.2초로 제한하며 한도와 실패를 `UIA_PARTIAL`로 보고합니다. 응답하지 않는 제공자는 기존 비동기 시간 제한으로 격리하며 OCR을 계속 시도합니다. 블로킹 중인 Windows 제공자 호출 자체를 강제로 취소하지는 않습니다.
- 로그 영역을 선택해도 해당 영역 안의 직접 읽기와 OCR을 병행합니다. 영역 밖의 정보로 상태를 보완하지 않습니다.
- 등록 외 번호 한 행 때문에 정상 객실까지 차단하던 처리를 수정했습니다. 번호·상태가 충돌하면 관련 객실·항목을 `uncertainFields`로 보류하고 독립된 정상 객실은 계속 전송합니다. 충돌한 OCR 프레임은 다음 판독의 확인 근거에서 제외합니다. 여러 객실이 섞인 행과 부정·오류 상태는 해당 객실의 문·키를 모두 보류합니다.
- 트레이와 판독 미리보기에 `글자 → 상태 해석 → 채택` 건수를 표시합니다. 전송 건수는 연결 보고를 포함한 묶음 수임을 명시했습니다. 시각 없는 상태표, 해석되지 않는 상태 어휘, 과거 이벤트만 존재, 충돌, 오래된 상태표를 구분합니다.
- 확인 필요 상태가 15초간 지속되면 Windows 알림을 표시하고 클릭 시 미리보기를 엽니다. 지속 중 재알림은 10분 간격이며 회복 후 다시 실패하면 새로 안내합니다. Windows 알림 설정과 관계없이 트레이·미리보기·로그에도 상태가 남습니다.
- `capture-status.json`에 단계별 건수와 실패 사유별 행 수를 남깁니다. 기존 진단 ZIP으로 수집할 수 있습니다. 대시보드에는 각 채널 원문을 최대 50줄씩 남겨 UIA 메뉴 텍스트가 OCR 증거를 모두 밀어내지 않도록 했습니다.
- 현장 시험의 이전 정상 판독을 선택하더라도 최신 화면에서 그 항목이 불확실하면 확인을 저장하지 못하게 했습니다.

## 설치 후 확인

1. 선택한 RMS 창에서 이벤트 내역을 열고 객실·발생 시각·문/키 상태 열을 모두 표시합니다. 이벤트 내역이 별도 창이면 연결 설정에서 그 창을 선택합니다.
2. 판독 미리보기에서 원문과 `채택` 건수를 봅니다. 글자만 늘고 채택이 0이면 위쪽 안내와 각 행의 실패 사유를 따릅니다.
3. 시각 없는 문·키 상태표이면 대시보드의 **화면·객실 설정**에서 의미를 확인하고 설정합니다. 로그 시각을 임의로 생성하거나 재실·청소중을 키 삽입으로 간주하지 않습니다.
4. 과거 이벤트만 있으면 시험 객실의 문 열기·닫기, 키 꽂기·빼기를 실행합니다. 해당 객실·시각·상태가 원문 및 수신 값과 일치하는지 **실제 문·키 동작 확인**으로 대조합니다.
5. 계속 채택이 0이면 트레이에서 진단 ZIP을 내보내고, 제조사·제품 버전과 실제 이벤트 한 줄을 함께 확보합니다. 아이콘·색상만 있거나 필요한 정보 자체를 노출하지 않는 RMS는 별도 연동 방식이 필요합니다.

## 검증 범위

공통 C# 회귀 테스트에 부분 성공, 객실 번호 충돌, 행 내부 충돌, 충돌 이후 OCR 복구, 과거 이벤트 안내, 알림 지연·복구를 추가했습니다. 서버 테스트는 정상 객실 유지와 최신 불확실 상태의 현장 확인 차단을 검사합니다. Windows CI의 실제 UI 테스트에는 깊게 중첩된 표, DataGridView 셀 값, 영역 제한, 비밀번호 제외를 추가했습니다.

Windows 테스트 창의 성공은 실제 제조사 RMS의 연동 인증이 아닙니다. 실제 PC에서 위 네 동작을 대조해야 합니다. 배포 여부는 README의 현재 배포 버전과 Windows 검증 기록을 확인하세요.
