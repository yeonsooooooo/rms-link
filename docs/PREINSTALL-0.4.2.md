# 0.4.2 설치·배포 검증 기록

2026-09-22에 Windows 실행·설치 검증을 통과한 0.4.2를 배포했습니다. 고객용 설치 파일과 자동 업데이트 패키지를 각각 검증하고 활성화했습니다.

## 확인된 문제와 수정

- HTTP 시간 초과가 백그라운드 전송 작업을 종료할 수 있었습니다. 종료 요청과 시간 초과를 구분하고 암호화 대기열을 재전송합니다.
- 설정 창이 서버 등록 확인 없이 닫혔습니다. HTTPS 서비스 응답·기기 등록·호텔 연결 보고를 확인하며 실패 위치와 조치를 표시합니다.
- 등록권 만료 시 설치 파일을 다시 만들어야 했습니다. 대시보드에서 새 코드를 발급하고 Windows 설정에 입력해 복구합니다.
- 설치를 별도 폴더의 실행 점검 후 적용하며, 재설치 시 설정과 자동 시작 선택을 보존합니다. 손상된 EXE는 OS 실행 전에 형식을 검사해 명확히 거부합니다.
- 설치 관리자·서버 연결·화면 판독 상태를 기록합니다. 앱이 없거나 설정이 손상돼도 독립 진단 수집이 가능하고, PowerShell 스크립트가 제한되면 CMD 파일 복사로 진단 ZIP/폴더를 만듭니다.
- 작은 화면에서도 설정 창을 스크롤하여 연결 버튼에 접근할 수 있습니다.
- Vercel 경유 관제의 간헐적 502를 확인하여 첫 접속 주소를 기존 공개 HTTPS 관제로 이동하도록 변경했습니다. 기존 인증과 데이터는 유지됩니다.

## 통과한 검증

- C# 공통 검사 91개, 서버 검사 22개와 대시보드 브라우저 검사.
- Windows 실제 시험 창의 UI Automation·OCR·가림 캡처·최소화 복원·창 재탐색.
- Windows의 실제 전송 작업에서 시간 초과 후 재시도, 암호화 대기열 재전송, 수신 확인, 거부된 자료 보존.
- 일반 설치 UI와 설정 창 시작 확인, 작은 화면 설정, 재설치 시 사용자 설정 유지, 손상된 EXE 설치 실패 시 이전 버전 보존.
- Windows PowerShell 5.1 진단 수집과 Restricted 정책 환경의 CMD 대체 수집.
- 배포할 비공개 EXE 자체를 별도로 내려받아 SHA-256 대조, 설치·설치된 앱 자체 검사·한글 바로가기 실행·자동 시작 등록 확인.
- 운영 HTTPS에서 등록권 만료 응답·새 코드 등록·연결 보고 확인. 임시 기기는 삭제했습니다.
- 운영 다운로드 파일 전체의 크기·SHA-256 및 서명된 자동 업데이트 안내와 실제 패키지를 대조했습니다.
- 배포된 관제 진입 주소의 307 이동·로그인·권한 제한·동일 데이터·새 등록 코드 발급·진단 다운로드·실시간 연결·로그아웃을 검사했습니다. 이 검사에서 오류 재시도는 없었습니다.

## 현장 확인 범위

과거 현장 실패의 정확한 위치는 현장 로그가 없어 아직 확정하지 못했습니다. Windows 시험은 시험 창과 검증 환경에서 수행했으며 실제 제조사 키텍과 물리 문·키는 조작하지 않았습니다. 한 시험 객실에서 문 열기·닫기, 손님 키 꽂기·빼기 네 동작을 대조하고 대시보드에 기록해야 해당 호텔의 연동 완료로 판단합니다.

설치 EXE는 Authenticode 서명이 없습니다. 조직 정책에 따른 실행 차단은 차단 문구와 독립 진단 도구로 확인하세요. RSA 업데이트 서명은 Windows 배포자 서명과 별개입니다. [현장 설치·복구 순서](INSTALL-RECOVERY.md)를 참고하세요.
