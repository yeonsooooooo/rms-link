# 0.4.2 검증 상태 (2026-09-22)

## 현장 실패에 대한 확인 결과

운영 데이터베이스에는 등록된 현장 기기가 없었습니다. 외부 기기 서버와 Vercel 경유 `/health`는 모두 RmsLink 정상 응답을 반환했습니다. 현장 PC의 로그가 없어 과거 실패 위치는 아직 확정하지 못했습니다.

기존 0.4.1 설치본의 등록권 만료 시각은 2026-09-24 18:55 KST입니다. 이 만료가 이번 현장 실패의 원인이었다고 단정하지 않습니다.

코드에서 확인해 수정한 문제:

- HTTP 시간 초과가 취소 예외로 처리되어 백그라운드 전송 작업이 종료될 수 있었습니다. 실제 종료 요청과 시간 초과를 구분해 재시도합니다.
- 설정 창은 서버 등록 확인 없이 닫혔습니다. 서버 정체성·기기 등록·호텔 연결 보고를 확인하고 실패 시 같은 창에 사유를 남깁니다.
- 등록권 만료 시 새 설치본이 필요했고 서버의 상세 사유가 Windows에 표시되지 않았습니다. 인증된 대시보드에서 새 코드를 발급하고 기존 앱에 입력할 수 있습니다.
- 설치는 실행 점검 없이 기존 폴더에 압축을 풀었습니다. 별도 폴더에서 검사하고 파일을 적용하며 적용 예외 시 이전 파일을 복구합니다.
- 진단 수집이 정상 설치된 앱에 의존하고 설치 관리자 로그를 빠뜨렸습니다. 앱이 없어도 동작하는 독립 수집기와 비밀값을 제외한 단계별 기록을 추가했습니다.
- 구형 install.ps1은 실제 설치 없이 안내만 출력하고 정상 종료했습니다. 인접 설치 EXE를 실행하거나 명확히 실패하도록 변경했습니다.

## 완료된 로컬 검증

- C# 공통 검사 91개 통과: 판독·업데이트 복구·서버 응답 검사·등록권 만료·설치 전/손상된 설정에서의 진단 수집·비밀값 제외.
- Node 서버 검사 22개 통과: 기존 수집·인증·현장 대조와 등록권 만료/소진/재발급/인증/재등록.
- 대시보드 브라우저 검사 통과: 새 코드 발급, 진단 ZIP 다운로드, 기존 화면·상세·모바일·일시 오류 복구.
- Windows 앱, 설치 관리자, Windows 전송 회귀 시험 프로젝트의 macOS 교차 빌드 성공.
- 독립 진단 ZIP 구조와 압축 무결성 확인.

## 아직 실행하지 못한 검증

Windows 전송 시험과 설치·재설치·손상된 EXE 설치 실패·설정 창 시작·PowerShell 진단 수집 시험은 CI에 준비했습니다. Windows에서 실제 실행한 결과는 아직 없습니다. GitHub 업로드가 자동 승인 검토에서 거부되어, 공개 저장소로 변경 코드를 보내는 사용자 승인을 기다립니다.

고객용 설치 EXE를 새 버전으로 전환하거나 자동 업데이트를 배포하지 않았습니다. 실제 호텔의 문·키 네 동작 대조도 수행하지 않았습니다. 이 문서는 0.4.2 현장 성공이나 배포 완료의 증명이 아닙니다.
