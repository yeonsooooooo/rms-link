# RMS-Link 0.4 화면 연동 범위

RMS-Link는 사용자가 선택한 Windows 프로그램의 화면·접근성 속성만 읽습니다. RMS 데이터베이스, 제조사 통신 프로토콜, 시리얼/USB 장치, 프로세스 메모리는 읽지 않습니다. 문 열기나 키 발급 명령을 보내지 않습니다.

## 설치 후 흐름

1. Windows x64 설치 → 호텔 ID → 실제 RMS 창과 제조사 선택 → 미리보기 확인.
2. RMS의 로그인 및 객실 상태/이벤트 화면은 사용자가 엽니다. 로그인 세션 안에서 저장된 연결이 자동 재개됩니다.
3. 호환되는 텍스트 로그는 기본 규칙으로 수집합니다. 대시보드가 상태표를 제안하거나 번호·문구가 다르면 화면·객실 설정과 호텔별 규칙으로 보정합니다.
4. 시험 객실에서 문 열기·닫기, 손님 키 삽입·제거를 수행하고 최근 판독과 대조해 저장합니다.

## 제조사 범위

| 제조사 | 현재 제공하는 경로 | 실제 제품 검증 |
| --- | --- | --- |
| 가람 | 명시적 앱 선택 + 공통 접근성/OCR + 호텔 규칙 | 실제 제품·버전·화면 샘플 필요 |
| 씨리얼 | 동일 | 실제 제품·버전·화면 샘플 필요 |
| 루넷 | 동일 | 실제 제품·버전·화면 샘플 필요 |
| 더엠알 | 동일 | 실제 제품·버전·화면 샘플 필요 |
| 로마시스 | 동일 | 실제 제품·버전·화면 샘플 필요 |
| 우연티앤이 | 동일 | 실제 제품·버전·화면 샘플 필요 |

이 목록은 사용자가 제공한 우선 검증 대상입니다. 각 제조사 전용 드라이버나 검증되지 않은 사전을 배포하지 않습니다. 제조사명이 같아도 RMS 제품, PMS 화면, 버전·글꼴·화면 배치가 다를 수 있습니다. 특정 제조사의 실물 지원률·정확도 수치를 제시할 실측 자료는 아직 없습니다.

## 판독 정책

- 접근성은 실제 Text, DataItem, ListItem 행과 셀의 이름/값을 읽으며 한 번 소비한 결과를 다음 화면의 증거로 재사용하지 않습니다. 응답이 멈추면 작업을 무한 생성하지 않고 OCR을 사용합니다.
- OCR은 Windows 엔진을 사용하고 단어 좌표로 같은 높이의 표 행을 재조합합니다. 한 줄에 여러 객실이 합쳐지면 보류합니다.
- UIA 일부 성공에도 OCR을 병행합니다. 동일 객실·필드·시각의 상태가 상충하면 해당 관측을 정상 상태로 전송하지 않습니다.
- OCR 단독 값은 연속 두 번 같아야 합니다. 화면을 읽지 못하거나 앱·영역·프로필이 바뀌면 이전 OCR 확인을 이어 쓰지 않습니다. 따라서 짧게 나타났다 사라지는 로그는 놓칠 수 있으며 검증되지 않은 단일 프레임은 확정하지 않습니다.
- `expectedRooms` 목록 밖의 번호를 차단합니다. 실제 목록 안의 다른 객실로 반복 오인식하는 경우에는 현장 대조가 필요합니다. 목록이 없으면 번호 검증 미완료를 안내합니다.
- 현재 상태표의 문/키 근거 시각은 각 상태가 달라질 때만 갱신됩니다. 한 객실이나 필드의 변화가 다른 필드의 오래된 상태를 갱신하지 않습니다. 값 변화 또는 검증한 RMS 데이터 갱신 시각이 60초 이내일 때만 현재 근거로 사용합니다.
- `liveClockPattern`을 쓰려면 첫 캡처 그룹이 실제 RMS 데이터 갱신 시각 HH:mm:ss를 읽어야 합니다. 현재와 60초 이상 차이, 미래 시각, 채널 간 큰 시각 차이는 채택하지 않습니다. 시계가 움직인다고 실제 센서 통신까지 정상이라고 증명할 수는 없습니다.
- 네트워크 재전송은 이미 읽은 자료를 보존합니다. 읽기 전에 화면에서 사라진 내용은 복원하지 않습니다.

## 창 상태와 복구

보이는 창은 화면 캡처, 가려진 창은 PrintWindow를 사용합니다. 해당 RMS가 PrintWindow를 구현하지 않으면 창을 보이게 해야 합니다. 최소화 시 자동 복원을 켜면 창이 다시 표시되며 포커스가 바뀔 수 있습니다. 최소화를 유지한 채 수집하는 기능은 아닙니다. Windows 잠금·로그아웃·RDP 연결 해제 등으로 로그인 데스크톱이 없으면 수집하지 않습니다.

## 현장 확인의 의미

확인 기록은 최근 승인된 판독의 원문·객실·코드·기기·호텔·프로필 버전·실행 파일 식별자·선택 창·영역·수집기 버전에 연결됩니다. 네 동작은 같은 시험 객실에서 확인해야 합니다. 청소키는 손님 키 확인을 대신하지 않습니다. 앱/창/영역/규칙 변경 뒤에는 기존 확인을 현재 검증으로 사용하지 않습니다.

기존 C# 파서와 동일한 실행기로 사전·객실 규칙을 검증합니다. 확인 샘플은 해석 규칙에 대한 증거이며, 테스트용 화면의 성공은 제조사 실물 연동 완료가 아닙니다.

## 남아 있는 화면 유형

아이콘·색상만 있는 상태판, 자동 스크롤/페이지/탭 탐색, 모든 객실을 동시에 보여주지 않는 카드 UI의 전용 판독은 제공하지 않습니다. 실제 화면 샘플 없이 임의의 색상을 키 삽입으로 해석하지 않습니다. 텍스트 로그를 표시할 수 있으면 그 화면을 선택하고, 그렇지 않으면 해당 제품의 검증된 화면 어댑터가 추가로 필요합니다.

## 검증 명령

`dotnet run --project tests/core/Core.csproj -c Release`로 공유 판독 정책을 검사합니다. 최신 Core 실행기를 publish한 후 `RMSLINK_CORE=<절대경로> npm test`와 `npm run test:ui`를 실행합니다. Windows CI는 테스트용 실제 창에서 접근성, OCR 두 프레임, 가림 캡처, 실제 최소화 거부·복원을 검사합니다. 모든 보고서는 테스트용 화면임을 표시하며 `physicalKeytechVerified=false`를 유지합니다.
