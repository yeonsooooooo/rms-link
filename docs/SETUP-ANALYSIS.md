# RmsLink 설치·설정·화면 분석 매뉴얼

버전 0.3.1 · 2026-09-15

## 1. 대시보드와 바탕화면 아이콘

현재 관리 컴퓨터의 **RmsLink 대시보드** 아이콘을 두 번 클릭하면 관제가 열립니다. 내부와 외부 대시보드는 같은 서버와 데이터베이스를 사용합니다. 외부 접속은 대시보드의 **외부 접속 · 바로가기**에서 주소와 접속 코드를 확인하세요. 외부에서는 접속 코드를 입력하면 12시간 동안 로그인됩니다. 코드는 운영 담당자끼리만 공유합니다. 기기 인증키나 Windows 설치 파일에는 관리자 접속 코드가 들어가지 않습니다.

외부 접속 주소는 [https://rms-link.vercel.app/](https://rms-link.vercel.app/)입니다. 기존 접속 코드를 그대로 사용합니다. Vercel 주소는 현재 운영 서버로 연결되므로 어느 주소에서 접속해도 동일한 호텔 정보와 분석 결과를 봅니다. Windows 설치 파일은 다운로드 버튼을 누르면 별도 다운로드 주소에서 받아지며 정상 동작입니다.

Windows 설치 후 만들어지는 아이콘:

| 아이콘                              | 역할                                                             |
| ----------------------------------- | ---------------------------------------------------------------- |
| **RmsLink 대시보드** · 초록색 네 칸 | 어디서든 호텔 현황·수집 화면·이벤트 확인                         |
| **RmsLink 연결 설정** · 초록색      | 호텔 ID 입력, 키텍 앱 선택, 수집 설정                            |
| **키텍 앱** · 파란색 열쇠           | 사용자가 확인한 실제 키텍 프로그램 실행. 앱 선택을 완료하면 생성 |

대시보드의 **외부 접속 · 바로가기 → Windows 바탕화면 바로가기 다운로드**는 관제용 PC에 설치 프로그램 없이 바로가기를 추가하는 방법입니다. 다운로드한 `.url` 파일을 바탕화면으로 옮기세요. 키텍을 수집하는 호텔 PC에는 Windows 설치 프로그램이 필요합니다.

새로 다운로드한 바로가기는 Vercel 주소를 엽니다. 기존 Windows 설치본의 바로가기는 기존 주소를 열며 같은 대시보드에 연결됩니다. Vercel 주소로 바꾸려면 새 바로가기로 교체하세요. **RmsLink 연결 설정**의 서버 주소는 기기 수집용이므로 변경할 필요가 없습니다.

외부에서도 데이터가 같으려면 서버 컴퓨터와 호텔 PC가 켜져 있고 인터넷에 연결되어 있어야 합니다. 서버는 재부팅 후 사용자 로그인이 필요하며 절전 중에는 접속할 수 없습니다. 외부 화면이 열리지 않으면 서버의 네트워크, HTTPS 중계 연결, 서버 프로세스를 확인합니다.

## 2. Windows에서 최초 연결

1. 대시보드의 **Windows 설치 파일**에서 최신 `RmsLink-Setup.exe`를 받습니다. Windows x64용이며 별도의 .NET 설치가 필요 없습니다. 지원 API 기준은 Windows 10 1809 이상입니다. 보안 업데이트가 제공되는 Windows 환경을 사용하세요.
2. 설치 프로그램 실행 후 **실제 호텔 ID**를 입력합니다. 예: `9`, `10`. 일반 실행 때마다 호텔을 확인하며 자동 업데이트 재시작은 현재 호텔을 유지합니다.
3. **바탕화면 아이콘에서 키텍 앱 선택**을 누릅니다.
4. 왼쪽에서 평소 사용하던 키텍 아이콘을 두 번 클릭합니다. 아이콘이 없으면 **아이콘/실행 파일 찾기**로 `.lnk` 또는 `.exe`를 고릅니다. 바로가기의 기존 실행 인수와 작업 폴더가 유지됩니다.
5. 키텍에 로그인해 객실 현황 또는 이벤트 로그 화면을 엽니다. **실행 중인 창 새로고침**을 누르고 오른쪽에서 실제 키텍 창을 선택합니다. 실행기가 다른 프로그램을 열었다면 그 실제 프로그램의 창을 선택하세요.
6. 아래 미리보기가 키텍 화면과 일치하는지 확인하고 **이 화면이 키텍 앱입니다 · 연결**을 누릅니다. 확인 없이 프로그램 이름만 보고 자동 지정하지 않습니다.
7. **이 호텔의 키텍 연결 시작**을 누릅니다. 바탕화면의 **키텍 앱**은 선택한 프로그램을 실행하는 명확한 이름과 열쇠 아이콘으로 만들어집니다.
8. 대시보드에서 해당 호텔과 PC를 클릭합니다. **선택한 키텍 앱**, 실행 프로그램, 이미지, 판독 원문, 마지막 수집 시각을 확인합니다.

다른 호텔 ID를 입력하면 그 호텔의 키텍 앱을 다시 선택해야 합니다. 실행 중에는 작업표시줄 오른쪽 RmsLink 아이콘 메뉴의 **키텍 앱 선택 · 변경**으로 대상을 바꿉니다. **호텔 ID 변경**은 연결 설정을 다시 엽니다. 이미 실행 중인 RmsLink 아이콘을 다시 열면 트레이 위치를 안내합니다.

## 3. 화면 수집 방식과 Windows 조건

- **텍스트 수집:** 기본 1.5초 주기입니다. 호텔별 규칙의 `pollMs`로 바꿀 수 있습니다. 접근성(UI Automation)으로 읽을 수 있는 실제 행을 우선 사용하고, 판독 가능한 행이 없으면 Windows OCR로 이미지의 글자를 읽습니다.
- **화면 이미지:** 공유 체크가 켜져 있으면 최대 5초 간격으로 전송합니다. 수집·OCR 처리 시간과 네트워크 지연이 더해집니다. 동영상 스트리밍은 아니며 정지 이미지가 주기적으로 갱신됩니다. 이미지 공유를 꺼도 판독 텍스트와 연결 진단은 전송됩니다.
- **창 추적:** 선택한 실행 파일과 창 식별자를 함께 확인합니다. 창 이동을 따라가고, 재실행 후 같은 실행 파일의 유일한 창 또는 일치하는 창 제목을 다시 찾습니다. 여러 창을 구분할 수 없으면 다시 선택하도록 안내합니다.
- **가림:** 온전히 보이는 키텍 창만 화면에서 캡처합니다. 다른 창에 가렸으면 해당 창의 인쇄 캡처 API를 시도합니다. 응답 지연이나 빈 이미지이면 원인을 표시합니다. 일부 GPU·원격 앱의 창 캡처는 지원되지 않을 수 있으므로 키텍 창을 앞으로 가져오세요.
- **잠금·최소화:** 정상적인 실시간 화면으로 취급하지 않습니다. Windows 로그인 세션을 유지하고 키텍 창을 복원하세요. 로그아웃, 사용자 전환, 원격 데스크톱 연결 해제 후에는 실제 이미지 갱신을 다시 확인합니다. 화면 수집은 Windows 서비스의 Session 0에서 실행하지 않습니다.
- **권한:** 키텍만 관리자 권한이면 접근성 조회나 창 캡처가 제한될 수 있습니다. 두 앱의 권한을 확인하세요. 필요한 경우 관리 담당자가 동일 권한으로 실행합니다. 보안 설정을 해제하거나 UAC를 우회하지 않습니다.
- **DPI·여러 모니터:** 전체 창은 현재 물리 픽셀 위치를 사용합니다. 다른 배율의 모니터로 이동하거나 해상도를 바꾸면 미리보기를 확인하세요.

### 로그 영역만 좁히기

1. 트레이의 **로그 영역 다시 지정**을 누릅니다.
2. 키텍 창 안에서 **객실 번호 + 상태 문구 + 발생 시각**을 포함해 드래그합니다. 지정 영역은 키텍 창 기준 상대 좌표로 저장되어 창 이동을 따라갑니다.
3. 키텍 창 크기·화면 배율·내부 패널 배치가 바뀌면 다시 지정합니다. 지정 영역이 창 밖으로 나가면 수집을 중단하고 오류를 표시합니다.
4. 전체 창으로 돌아가려면 **키텍 앱 선택 · 변경**으로 다시 선택합니다. 기존 영역은 초기화됩니다.

한국어 OCR이 없으면 Windows **설정 → 시간 및 언어 → 언어 및 지역 → 한국어 → 언어 옵션**에서 관련 언어 기능을 설치합니다. 관리 환경에서는 관리자 PowerShell에서 `Get-WindowsCapability -Online -Name 'Language.OCR*'`로 확인하고 `Add-WindowsCapability -Online -Name 'Language.OCR~~~ko-KR~0.0.1.0'`로 추가할 수 있습니다. 설치 후 RmsLink를 다시 실행합니다.

## 4. 대시보드에서 분석하는 순서

**대시보드 → 호텔·기기 클릭 → 화면 → 원문 → 오류 → 확인 샘플 → 지금 화면 분석** 순서로 확인합니다.

### A. 화면이 맞는지 먼저 확인

**선택한 키텍 앱**과 이미지가 현장 키텍 창인지 대조합니다. 이미지 저장 시각과 텍스트 수집 시각은 별도로 표시됩니다. **마지막 저장 화면 · 현재 화면 확인 필요**이면 과거 이미지입니다. 화면이 틀리면 Windows에서 앱을 다시 선택하고, 이미지가 멈췄으면 잠금·최소화·가림·연결 상태부터 해결합니다.

### B. 글자를 읽었는지 확인

**판독 원문과 실패 사유**를 봅니다. 이미지에는 글자가 있지만 원문이 비어 있거나 잘못됐으면 한국어 OCR, 글자 크기, 로그 영역을 확인합니다. 원문이 정확한데 이벤트만 없으면 객실 번호, 상태 어휘, 발생 시각 형식 문제일 가능성이 있습니다. UI Automation 실패 후 OCR이 정상이라면 접근성 경고 자체가 키텍 연동 실패를 뜻하지는 않습니다.

### C. 화면의 의미 결정

- **이벤트 로그(`events`)**: 발생 시각이 있는 문 열림·닫힘, 키 삽입·제거 기록. 마지막 이벤트로부터 현재 상태를 추정합니다. 화면에 과거 로그만 있을 때 모든 객실의 현재 상태를 알 수 있는 것은 아닙니다.
- **현재 상태표(`snapshot`)**: 화면에 객실별 현재 문·키 상태가 명시되어 있을 때 사용합니다. 문·키 상태가 직접 적혀 있고 현장과 일치하는지 검증한 후 적용합니다.
- **아이콘·색상만 있는 화면**: OCR 어휘 추가만으로 해결할 수 없습니다. 접근성 속성, 제조사 제공 데이터 또는 검증된 화면 판독 방식이 추가로 필요합니다. 색을 보고 임의로 ‘키 꽂힘’으로 확정하지 않습니다.

### D. 실제 동작과 대조한 샘플 등록

시험 객실 한 곳에서 다음을 차례로 실행합니다. 다른 객실의 이벤트와 섞이지 않도록 객실·시각을 기록하세요.

| 실제 동작        | 기대 코드                                           |
| ---------------- | --------------------------------------------------- |
| 문 열기          | `DOOR_OPEN`                                         |
| 문 닫기          | `DOOR_CLOSE`                                        |
| 손님 키 꽂기     | `KEY_IN` 또는 `KEY_IN_GUEST`                        |
| 손님 키 빼기     | `KEY_OUT` 또는 `KEY_OUT_GUEST`                      |
| 청소키 꽂기·빼기 | 화면이 구분할 때만 `KEY_IN_CLEAN` / `KEY_OUT_CLEAN` |

누락된 행은 **확인한 판독 샘플 등록**에서 화면에 실제로 나온 원문, 실제 객실 번호, 실제 상태를 기록합니다. 예: 원문 `101 고객키투입 12:03:10`, 객실 `101`, 실제 상태 `손님 키 꽂힘`. 이미지나 현장 동작을 보지 않고 추측한 상태는 등록하지 않습니다.

### E. 분석 요청과 결과 해석

**지금 화면 분석**을 누르면 최신 관측, 가까운 시각의 이미지, 호텔별 규칙, 확인 샘플을 분석합니다. 서버의 분석 실행 계정이 로그인되어 있어야 합니다. 수집 정보와 이미지는 원격 AI 분석 서비스로 전달될 수 있습니다.

- **원인 분석 완료:** 제시된 조치를 현장에서 수행하고 재확인합니다.
- **확인 자료 필요:** 실제 동작과 대조한 샘플을 추가하고 다시 분석합니다.
- **프로필 배포:** 제안된 어휘가 확인 샘플·공통 회귀 검증을 통과해 해당 호텔에 배포됐습니다. Windows의 프로필 revision이 증가하는지 확인합니다.
- **분석 실패/중단:** 오류 상세를 확인합니다. 분석 실행 계정의 인증·사용량·네트워크·서버 프로세스를 점검하고 다시 요청합니다.
- **코드 수정 필요:** 캡처 방식, 아이콘 판독 등은 별도 구현·Windows 검증·새 앱 배포가 필요합니다. 자동 분석은 임의의 실행 코드를 생성해 설치하지 않습니다.

자동 분석은 중복 실패를 억제하며 하루 최대 4건입니다. 수동 버튼의 거부/대기 안내도 확인하세요. 정상 캡처·연결 상태와 실제 문·키 의미의 정확성은 별도로 검증해야 합니다.

### F. 규칙 직접 수정과 재검증

**호텔별 규칙 편집**에서 `mode`, `aliases`(화면 어휘→이벤트 코드), `roomMap`(화면 번호→실제 객실), `pollMs`, `ocrScale`을 설정할 수 있습니다. 정확한 원문과 기대 상태를 먼저 샘플로 등록합니다. JSON 저장 시 공통·호텔별 C# 판독 검증을 통과해야 배포됩니다. 객실 재실·청소중·공실만으로 키 상태를 대신 판독하지 않습니다.

Windows의 **지금 업데이트 확인 · 적용**으로 새 규칙을 즉시 받고 같은 문/키 시험을 반복합니다. 잘못된 규칙은 대시보드 **업데이트**에서 이전 규칙으로 복구할 수 있습니다. 문 열기·닫기·키 삽입·제거가 모두 현장과 일치한 뒤 호텔 연동 완료로 기록합니다.

## 5. 연결·업데이트·복구

기기는 2분마다 앱·프로필 업데이트를 확인합니다. 새 앱은 서명·크기·해시 확인과 실행 점검 후 적용하며 실패하면 이전 버전으로 복구합니다. 첫 업데이트로 키텍 앱 선택이 필요한 경우 선택 창이 표시됩니다. 네트워크 단절 시 암호화 전송 대기열을 유지하고 복구 후 재전송합니다. 과거 자료는 최신 상태를 덮어쓰지 않습니다.

객실 상태의 현재 화면 근거는 1분, 이벤트 근거는 5분, 기기 연결은 45초가 신선도 기준입니다. 수집 오류가 있으면 정상 상태로 확정하지 않습니다. 화면의 마지막 저장 이미지와 과거 상태는 참고용으로만 봅니다.

현재 배포본의 실제 제조사 키텍·호텔별 화면은 현장 확인이 필요합니다. 공인 Windows 코드 서명이 없는 설치본이면 조직 정책에 따른 실행 차단이 나타날 수 있습니다. 운영 담당자가 배포 출처와 파일을 확인하세요.
