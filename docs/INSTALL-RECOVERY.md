# 설치·연결을 완료하는 순서와 실패 진단 (0.4.2)

설치 파일 실행, 프로그램 설치, 서버 등록, 화면 판독, 실제 문·키 대조는 각각 별도의 단계입니다. 파일 설치 성공만으로 호텔 연동 완료로 표시하지 않습니다.

## 현장 담당자가 할 일

1. 대시보드의 **Windows 설치 파일**에서 최신 파일을 받습니다. x64 Windows 10 1809 이상, 로그인한 사용자 세션에서 실행합니다.
2. 설치 진행 창에서 환경 확인 → 압축 해제 → 실행 점검 → 파일 적용 → 바로가기 → 연결 설정 창이 차례로 표시됩니다. 기존 앱이 켜져 있으면 트레이에서 종료하고 다시 설치합니다. 관리자 권한은 기본 설치에 필요하지 않습니다.
3. 실제 호텔 ID와 키텍 창을 선택하고 미리보기를 확인합니다. **서버 연결 확인 후 시작**을 누릅니다. HTTPS 서버 응답·기기 등록·호텔 연결 보고까지 성공해야 설정 창이 닫힙니다. 실패하면 같은 창에 단계 코드와 조치가 표시됩니다.
4. 등록권 만료나 사용 횟수 초과라면 대시보드 **Windows 설치 파일 → 새 등록 코드 발급**을 누릅니다. 48자리 코드를 Windows 연결 설정에 붙여넣고 다시 시도합니다. 코드는 7일/100대 한도입니다. 이미 등록한 기기는 만료된 코드로도 기존 인증을 계속 사용합니다. 코드 재발급은 기존 기기의 등록 중지를 해제하지 않습니다.
5. 판독 미리보기에서 오류·읽기 결과·전송 수를 확인하고, 대시보드에서 해당 호텔·기기가 실제로 갱신되는지 확인합니다. 화면 종류와 실제 객실 목록을 지정합니다.
6. 한 시험 객실의 문 열기·닫기, 손님 키 꽂기·빼기 네 동작을 현장과 대조해 저장합니다. 창 가림·최소화·앱 재실행·인터넷 재연결도 확인합니다. 이 현장 대조가 끝나야 해당 호텔의 연동을 완료로 판단합니다.

## 실패한 위치를 모를 때

대시보드 **Windows 설치 파일 → 앱 없이 실행하는 진단 도구**를 받습니다. ZIP 압축을 풀고 `collect-logs.cmd`를 실행합니다. 바탕화면에 만들어진 `RmsLink-diagnostics-날짜-번호.zip`을 운영 담당자에게 전달합니다. 앱 설치가 안 됐거나 설정 파일이 손상됐어도 실행할 수 있습니다. 조직 정책이 PowerShell을 차단하면 차단 문구를 기록하고 담당자에게 확인합니다.

설정 창이나 트레이의 **진단 파일 저장**도 같은 핵심 기록을 수집합니다. 폴더 쓰기 실패 시 임시 폴더를 사용합니다. 등록 코드·기기 암호·전송 대기열·화면 이미지는 진단 ZIP에 넣지 않습니다. 설치 기록, 서버 주소, PC 환경, 앱 선택 경로는 포함됩니다.

| 기록/코드 | 확인된 위치 | 다음 조치 |
|---|---|---|
| 설치 기록 자체가 없음 | 설치 관리자가 시작됐다는 증거 없음 | 다운로드 파일·Windows 버전·보안 차단 화면 확인. 실행 이전 차단 원인은 앱 코드로 확정할 수 없음 |
| `ENVIRONMENT` | 지원 OS/64비트 조건 | Windows 버전과 아키텍처 확인 |
| `EXTRACT` | 패키지 읽기/압축 해제 | 새로 다운로드, 설치 드라이브 여유 공간·쓰기 권한 확인 |
| `RUNTIME` | 이 PC의 앱 자체 실행 검사 | `install-runtime.json`, Windows 보안·응용 프로그램 기록 확인. 기존 버전은 적용 전 보존 |
| `ACTIVATE` | 검사한 파일 적용 | 기존 앱 종료·폴더 권한·보안 프로그램 파일 잠금 확인 |
| `SHORTCUTS` | 바로가기/자동 시작 | 앱 설치와 별도로 복구. 시작 메뉴 또는 설치 폴더의 Launcher 사용 |
| `APP_START` | 연결 설정 창 열기 | 앱 crash 로그 확인 |
| `SERVER_*` | DNS/HTTPS/서비스 응답 | 인터넷·프록시·인증서·PC 시각·서버/중계 상태 확인 |
| `ENROLL_*` | 기기 등록 | 새 등록 코드 입력 또는 기기 등록 중지 상태 확인 |
| `HEARTBEAT_*` | 호텔 연결 보고 | 호텔 ID와 기기 인증 확인 |
| `OBSERVATIONS_*` | 화면 자료 전송/서버 수락 | 서버·앱 버전과 거부된 자료 수 확인. 전송 실패는 재시도 |
| `CAPTURE` / `READING` | 창 캡처/글자·상태 해석 | 창 선택·잠금·가림·한국어 OCR·로그 영역·화면 규칙 확인 |

주요 파일은 `%LOCALAPPDATA%\RmsLink\installation-status.json`, `installer.log`, `install-runtime.json`과 `%APPDATA%\RmsLink\connection-status.json`, `capture-status.json`입니다. JSON에는 실행 ID, 단계, 상태, 기록 시각이 있습니다. 과거 성공 기록을 현재 연결 성공으로 간주하지 않습니다.

## 검증 범위

공통 C# 테스트는 서버 응답 검사, 시간 초과·등록권 만료 메시지, 설치 전/손상 설정 진단 수집 및 비밀값 제외를 검사합니다. 서버 테스트는 등록권 만료·소진·재발급·기존 기기의 재시도·권한을 검사합니다.

Windows CI는 실제 시험 창의 접근성/OCR/캡처, 설치 EXE 실행, 설치된 앱 자체 점검, 설정 창의 시작 확인, 재설치 시 사용자 설정 유지, 손상된 EXE 설치 실패 시 기존 버전 보존, 독립 진단 도구를 검사합니다. 배포할 비공개 설치 파일은 별도 Windows 검증을 통과해야 고객용 다운로드로 전환합니다.

실제 호텔의 네트워크 정책, Windows 보안 차단, 제조사 프로그램과 문·키 동작은 현장 검증이 필요합니다. 현재 설치 EXE는 Authenticode 인증서로 서명되지 않았습니다. RSA 업데이트 서명은 Windows 배포자 서명을 대신하지 않습니다.
