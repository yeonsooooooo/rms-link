# 0.4.1 설치 전 점검 기록

## 점검 결론

2026-09-17에 Windows 실행·설치 검증을 마치고 0.4.1을 배포했습니다. 대시보드의 다운로드 설치본과 활성 자동 업데이트가 모두 0.4.1입니다. GitHub CLI 로그인에 `workflow` 권한을 추가했고, 변경한 CI 워크플로를 추적 브랜치에 반영했습니다.

## 고친 부분

- 글자 직접 읽기(UI Automation)와 사진의 글자 읽기(Windows OCR)를 구분하고, 직접 읽기에서 글자 없음·응답 지연·오류·상태 해석 실패·검사 생략을 별도로 설명합니다.
- 원문, 사용한 상태, 저장된 이벤트에 방법을 남깁니다. 구버전 기록은 추정하지 않습니다.
- 사람이 직접 대조한 맞음과 틀림을 방법별로 기록합니다. 샘플 정답률은 전체 화면 정확도나 누락률이 아닙니다.
- UI Automation의 화면에 보이는 TextPattern 범위를 읽고, 행 이름과 열 값이 중복되어 객실 번호가 두 번 나오는 경우를 처리합니다.
- 캡처 중 창의 크기·위치·프로세스가 바뀌면 결과를 보류합니다.
- 자동 업데이트용 자체 검사를 CI의 화면·바로가기 시험과 분리하여 고객 바로가기를 덮어쓰지 않습니다.
- 연결 설정 바로가기는 설치 관리자를 통해 현재 버전을 실행합니다.
- 다운로드 중에도 연결 보고와 대기 전송을 계속하고, 다운로드에는 5분 제한을 둡니다.
- 새 앱 실행 실패·준비 신호 없음·중간 재시작 상황에서 이전 버전으로 복구하고 실패한 버전은 재설치를 보류합니다.
- 외부 중계의 일시 오류 때 대시보드 최초 연결 확인·데이터 조회를 한 번 재시도합니다. 저장 요청은 자동으로 중복 전송하지 않습니다.

## 통과한 시험

- C# 공통 판독·서명 검증·실제 자식 프로세스를 이용한 업데이트 성공/실패/복구: 67개.
- 서버·인증·수신·정확도 기록·자동 배포 조건·설치 후보 다운로드: 21개.
- Windows 앱 및 설치 관리자 교차 컴파일.
- 대시보드 상세, 맞음·틀림 기록, 현장 대조, 화면 설정, 모바일 너비, 최초 연결·데이터 조회의 502 오류 복구 검사.
- Windows의 시험 창에서 직접 읽기·보이는 TextPattern·OCR 두 프레임·창 선택·가림 캡처·최소화 복원·창 재탐색 검사.
- 배포할 설치 EXE를 Windows에서 실제 실행하여 설치 경로, 현재 버전, 바로가기, 로그인 시 자동 시작 등록, 설치된 앱 자체 검사 확인. 원래 한글 이름의 연결 설정 바로가기로 설정 창이 열리는 것까지 확인했습니다. 설치 버튼을 사람이 클릭하는 GUI 절차와 실제 Windows 재로그인은 이 자동 시험에 포함하지 않습니다.
- 운영 서버의 자동 배포가 Windows 검증 산출물을 받아 0.4.1을 활성화한 것 확인. 공개 HTTPS에서 임시 기기 등록 → 업데이트 안내 수신 → RSA 서명 검증 → 패키지 전체 다운로드·SHA-256 대조를 완료하고 임시 기기를 삭제했습니다.

- [최종 설치 파일의 Windows 설치·실행 검사](https://github.com/yeonsooooooo/rms-link/actions/runs/35209970738): 성공.
- Windows 앱 소스 커밋: `5fef2397e64e7ebbdda31321dadef546b63aec84`. 이후 변경은 서버 다운로드 처리, 대시보드 재시도, 검증 스크립트, 문서에 한정됩니다.
- 앱 업데이트 패키지 SHA-256: `4af4e14bb7d0faf54912e47e78cff799ecce763099c37ede50ff2e10d295822f`.
- 설치 EXE SHA-256: `8c46f18069fa540b75dcfd5af105f898435a2e5415f0a276e50b4afb6f74c4c0` (303,671,836 bytes). 대시보드의 실제 공개 HTTPS 다운로드를 끝까지 받아 같은 해시임을 확인했습니다.
- 로컬 상세 증거: `artifacts/verification-0.4.1.json`, `artifacts/installer-deployment-041.json`, `artifacts/published-installer-041.json`, `artifacts/release-delivery-041.json`, `artifacts/vercel-verification.json`.

설치본의 신규 기기 등록권은 2026-09-24 18:55 KST까지 유효합니다. 이후 신규 설치에는 등록권을 새로 넣은 설치본이 필요합니다. 이미 등록한 PC의 수집과 자동 업데이트는 이 등록권 만료에 영향받지 않습니다. 설치 EXE는 Authenticode 서명이 없어 Windows 보안 경고나 조직 정책의 차단이 있을 수 있습니다. 업데이트 안내의 RSA 서명 검증과는 별개입니다.

외부 관제 반복 검사에서 중계의 일시 오류와 502 응답을 관측했습니다. 이후 로그인·동일 데이터·설치 다운로드·실시간 수신·로그아웃을 포함한 전체 검사는 통과했습니다. 화면의 조회 재시도와 실시간 재연결을 검증했지만 외부 중계의 무중단 동작을 보장하지는 않습니다.

## 현장에서 확인할 것

실제 키텍 제품과 한국어 화면의 정확도는 아직 검증하지 않았습니다. 설치 후 한 객실에서 문 열기·닫기, 손님 키 꽂기·빼기를 각각 실행하고, 대시보드의 객실 번호·상태·원문·읽기 방식을 대조합니다. 최소화·다른 창에 가림·앱 재시작도 확인합니다. 화면에 없는 객실, 아이콘/색만 있는 정보, 과거 로그만 있는 화면에서는 현재 상태를 모두 확보할 수 없습니다.
