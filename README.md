# RmsLink · 키텍 관측과 지속 개선

Windows 호텔 PC에서 선택한 키텍/RMS 화면을 읽어 관리 서버에 전달하고, 원인 분석·호텔별 판독 규칙·검증된 앱 업데이트를 관리합니다. **실제 장치 연동 성공은 현장에서 문/키를 조작하고 수신 결과를 대조해야 확인됩니다.**

## 설치 실패 복구 (0.4.2)

설치와 서버 등록의 각 단계를 기록하고, 연결 성공을 확인한 뒤 수집을 시작합니다. 등록권 만료는 새 코드로 복구하며, 앱을 실행할 수 없어도 독립 진단 ZIP을 수집할 수 있습니다. [설치·복구 절차와 단계별 조치](docs/INSTALL-RECOVERY.md). 배포 버전은 대시보드 표시와 Windows 검증 기록을 확인하세요.

## 설치·접속

- 현재 컴퓨터: 바탕화면 **RmsLink 대시보드** 또는 [내부 대시보드](http://127.0.0.1:18760/).
- [외부 대시보드](https://rms-link.vercel.app/): 기존 공개 HTTPS 관제로 이동한 뒤 관리자 접속 코드로 로그인합니다. 내부와 같은 데이터·화면을 제공합니다.
- 현재 배포: **0.4.3**. 대시보드의 **Windows 설치 파일 · v0.4.3**에서 받습니다. [Windows 설치·업데이트 검증 기록](docs/PREINSTALL-0.4.3.md).
- **[설치·설정·화면 분석 매뉴얼](docs/SETUP-ANALYSIS.md)** — 대시보드에서도 열 수 있습니다.
- Windows 설치 → 호텔 ID 입력 → 바탕화면 아이콘으로 키텍 앱 선택 → 창 미리보기 확인 → 연결 시작.
- 설치·선택 후 **RmsLink 대시보드**, **RmsLink 연결 설정**, **키텍 앱** 아이콘이 생성됩니다.
- 선택한 실행 파일과 창만 추적합니다. 다른 앱으로 자동 전환하지 않습니다. 텍스트 기본 1.5초, 이미지 최대 5초 간격 수집이며 처리·네트워크 지연이 추가됩니다.

Windows x64, Windows 10 1809 이상을 대상으로 합니다. 로그인 세션 안에서 동작합니다. 최소화 시 자동 창 복원(설정에서 끌 수 있음)을 제공하며 잠금·지원하지 않는 캡처 화면은 현장 확인이 필요합니다. .NET 런타임을 포함한 설치 파일을 제공합니다.

## 구성

- **Windows:** RMS 후보 창 탐색 → UI Automation + Windows OCR 교차 판독 → OCR 연속 확인 → 객실 목록 검증 → DPAPI 암호화 outbox → HTTPS. RMS/도어락의 문을 여는 제어 명령은 없습니다.
- **관리 서버:** 기기 인증, SQLite 이벤트/진단 보존, 상태 신선도 계산, SSE 실시간 대시보드, AI 진단 큐.
- **호텔 프로필:** `hotel_id`별 어휘·객실 번호·판독 방식·OCR 배율·주기. 공통 규칙과 별개로 서명된 프로필을 배포합니다.
- **개선:** 실패 관측을 AI CLI에 전달합니다. 확인된 현장 샘플과 동일 C# 파서의 회귀 검증을 통과한 어휘 수정은 해당 호텔에 자동 배포합니다. 확인되지 않은 의미는 `needs_evidence`, 코드 수정이 필요한 경우는 구체적인 조치와 근거를 남깁니다. LLM 추측만으로 문·키 상태를 확정하지 않습니다.
- **앱 업데이트:** 코드 수정 + 버전 증가 + 추적 브랜치 push → Windows CI 빌드·실행 검증 → 관리 서버가 5분마다 검증 산출물 확인 → RSA 서명 안내 → Windows가 2분마다 자동 적용. 트레이 메뉴에서 수동 확인도 가능합니다. 새 버전 실행 확인 실패 시 이전 버전으로 복구하고 실패 버전 재설치를 보류합니다.

## 상태의 의미

`door`와 `key`는 별도로 갱신합니다. `snapshot`은 현재 화면에서 읽은 값, `event`는 마지막 발생 이벤트로 추정한 값입니다. 현재 화면은 60초, 이벤트는 5분, 기기 연결은 45초가 기준입니다. 오래됐거나 수집 오류가 있으면 `unknown/stale`로 표시합니다. 객실 입실/청소중/공실만으로 키 삽입을 추론하지 않습니다. 늦게 재전송된 이벤트가 최신 상태를 덮어쓰지 않습니다.

**첫 설치 시 모든 객실의 현재 키 상태가 자동으로 확보되는 것은 아닙니다.** RMS에 현재 상태표가 있으면 호텔 프로필을 `snapshot`으로 맞추고 현장 샘플을 검증하세요. 과거 이벤트 로그만 보이는 환경에서는 새로운 키/문 이벤트를 기다려야 합니다. 화면 외의 제조사 통신 프로토콜, 직접 DB, USB/시리얼 드라이버는 이번 수집기의 연결 방식이 아닙니다.

## 0.4 화면 판독과 현장 검증

- 가람·씨리얼·루넷·더엠알·로마시스·우연티앤이 및 기타 제조사를 선택하고 실제 실행 파일·제품 버전을 진단에 기록합니다. **제조사 선택은 지원 인증이 아닙니다.**
- 접근성 일부 행만 성공해도 OCR을 병행합니다. OCR 열은 화면 좌표로 행을 재구성하고 OCR 단독 값은 두 번 연속 같을 때 채택합니다. 상충하는 값은 보류합니다.
- 대시보드 **화면·객실 설정**에서 로그/현재 상태표와 실제 객실 목록을 지정합니다. 등록 외 번호는 차단하며 읽지 못한 객실도 미확인으로 표시합니다.
- 현재 상태표의 동일한 값은 재캡처만으로 근거 시각을 갱신하지 않습니다. 검증한 RMS 갱신 시각이 없는 경우 해당 문/키 값이 바뀐 뒤 60초가 지나면 미확인으로 전환합니다. 정상적인 정적 화면도 동일하게 처리하므로 멈춤 확정 표시가 아닙니다.
- **실제 문·키 동작 확인**은 최근 수신한 원문에 연결됩니다. 같은 시험 객실의 문 열기·닫기, 손님 키 꽂기·빼기를 확인하면 그 기기의 시험 결과가 기록됩니다. 앱·창·영역·판독 규칙 변경 시 재검증합니다.
- 저장된 연결은 Windows 로그인 후 자동 재개합니다. 연결 설정 바로가기와 트레이에서 호텔을 변경할 수 있습니다.

[화면 연동 범위와 검증 기준](docs/SCREEN-INTEGRATION.md). 아이콘/색상 판독과 자동 페이지 탐색, 실제 여섯 제조사의 현장 연동은 검증 완료로 주장하지 않습니다.

## 0.4.1 읽기 방식 구분

기기 상세의 **어떻게 읽었나요?**에서 직접 읽기 성공·빈 글자·해석 실패·응답 실패·영역 선택으로 검사하지 않음을 구분합니다. 각 원문·이벤트·객실 상태에 읽기 방법을 기록합니다. **방법별 결과 맞음·틀림 기록**은 사람이 대조한 샘플의 정답률이며 읽지 못한 행을 포함한 전체 정확도가 아닙니다.

자동 업데이트 검사를 개발용 화면 시험과 분리하고, 다운로드 중 연결 보고 유지와 실행 실패 시 복구를 보완했습니다. 새 설치 파일은 최신 설치 관리자를 포함합니다.

## 개발 및 검증

**0.4.3**은 일부 글자만 수집되고 연동이 진행되지 않는 상황을 개선합니다. 중첩된 표·셀 값·선택 영역의 접근성을 읽고 OCR과 대조하며, 불확실한 객실·항목만 보류합니다. 트레이·미리보기는 글자 수와 채택 상태 수를 구분하고, 15초 이상 확인이 필요하면 알림을 표시합니다. 자세한 변경과 현장 확인 절차는 [판독 복구](docs/READING-RECOVERY.md)를 참고하세요. Windows 실행·설치 및 운영 다운로드 검증을 통과했습니다.

Node 24+, .NET 8 SDK가 필요합니다. Windows 바이너리는 macOS에서도 교차 컴파일하며 실행 검증은 Windows CI에서 합니다.

```sh
npm ci
dotnet run --project tests/core/Core.csproj -c Release
dotnet publish tests/core/Core.csproj -c Release -r osx-arm64 --self-contained true -p:PublishSingleFile=true -o .work/core
RMSLINK_CORE="$PWD/.work/core/RmsLinkCore" npm test
dotnet build RmsLink.csproj -c Release
RMSLINK_CORE="$PWD/.work/core/RmsLinkCore" npm start
```
